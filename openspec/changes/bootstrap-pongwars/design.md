## Context

New Python/pygame project. Key requirements: 2 players (local or LAN), 1 vs AI,
configurable matches, extras, 8-bit pseudo-3D look, modularity, tests, Doxygen,
and localization.

## Goals / Non-Goals

**Goals**
- Simulation testable without screen or network.
- Add modes/arenas/extras/AI without modifying the core.
- Same simulation code for local, AI and LAN play.
- Every user-visible string translatable.

**Non-Goals**: see `proposal.md`.

## Decisions

### D1. Layered architecture with a pure `domain`
```
app -> ui -> render / input / audio / net -> domain <- ai      (core below all)
```
`domain` imports neither pygame nor sockets. `render`, `input`, `audio`, `net`
are adapters. *Discarded*: logic inside pygame sprites (hard to test and to
synchronize over the network).

### D2. Deterministic fixed-step simulation (60 Hz)
`World.step(inputs)` is a pure function of state and inputs; randomness only via
a seeded `RandomSource`. Enables replays, hypothesis tests and network sync.

### D3. "3D" = 2D physics + projection
Physics runs on the 2D table plane in world units; rendering projects the plane
with perspective (tilted camera) and gives height/shadows to paddles and
obstacles. *Discarded*: true 3D physics (complexity with no gameplay gain).

### D4. 8-bit look
Render to a low internal resolution (e.g. 320x180) offscreen `Surface`, limited
palette (<= 32 colors, `render/palette.py`), nearest-neighbor upscale, own bitmap
font. Sprites/sounds generated by code when possible.

### D5. Extensibility via `Registry` + data
Generic `Registry[T]` with decorator registration (`@register_mode("classic")`).
Arenas and extras are described in TOML/JSON validated against dataclasses;
special behaviour is implemented with registered `Effect`/`Mode` classes. Extras
are *effects* with hooks (`on_apply`, `on_tick`, `on_expire`); the core has no
per-type `if`.

### D6. Network: authoritative host over UDP
- Host runs the simulation; client sends **inputs** and receives **snapshots**
  (interpolated client-side, with sequence numbers).
- LAN discovery by UDP broadcast; critical messages (start, end, config) get
  minimal ACK/retry.
- Versioned protocol; serialization behind a `Codec` interface.
*Discarded*: deterministic lockstep (fragile with loss/jitter); TCP (head-of-line
blocking latency).

### D7. AI
`AIController` consumes an *observation* (not the mutable `World`) and returns a
`PlayerInput`. Difficulty = parameters (reaction time, prediction error, max
speed, extra usage) on a shared base strategy; new strategies are registered.

### D8. Configuration
`MatchConfig` (frozen dataclass): mode, arena, limits, enabled extras and
frequency, AI difficulty, controller per player, seed. JSON-serializable,
validated, with presets. It is the only object traveling from menu to simulation
to network.

### D9. Localization (i18n)
- `core.i18n` provides `Translator` (no pygame): loads JSON catalogs from
  `data/locales/<lang>.json`, flat dotted keys (`menu.main.play`), `{name}`
  placeholders, plural forms via `key.one`/`key.other`, fallback chain
  `selected -> en -> key`.
- Domain and net never emit text: events and errors carry **keys + params**; the
  UI layer translates. Locale is a user setting, never part of `MatchConfig`
  (so both LAN peers can use different languages).
- A test checks every non-English catalog has no unknown keys and reports
  missing ones; the English catalog is the source of truth.
- Bitmap font must support the glyph set a language needs; catalogs declare the
  required charset.
*Discarded*: gettext (heavier tooling, poor fit for bitmap fonts and data-driven
keys).

### D10. Tooling
src-layout, `pyproject.toml`, pytest, ruff, mypy, Doxygen (`docs/Doxyfile`).
Local CI via `scripts/check.ps1`.

## Risks / Trade-offs

- **Software pseudo-3D performance** -> low internal resolution, surface
  caching, benchmark early.
- **LAN latency/jitter** -> 30-60 Hz snapshots, interpolation, optional local
  prediction of own paddle.
- **Extras complexity** -> small composable effects with individual tests; cap
  on simultaneous effects.
- **pygame vs pygame-ce** -> `pygame-ce` (maintained), compatible API.
